# Starter Partner System Setup

## 1. Add project Asset Manager/cook rules

Create `/Game/DigimonData`, then merge `ConfigTemplates/DMF_Project_DefaultGame.ini.snippet` into `<YourProject>/Config/DefaultGame.ini`. Do not clear or replace your project's existing `PrimaryAssetTypesToScan` entries.

This registers `DMFDigimonSpecies` and `DMFStarterRoster` as Primary Asset types and marks them `AlwaysCook`, preventing data-driven species definitions from disappearing in packaged builds. UE5.8 currently does not automatically package plugin configuration files, which is why these entries are supplied as a project-config snippet rather than hidden in the plugin's Config folder.

## 2. Create Digimon species assets

Create **Data Asset → DMFDigimonSpeciesData** under `/Game/DigimonData` for every starter candidate.

Configure at minimum:
- Species Key
- Display Name / Description
- Stage / Attribute / Element
- Starting Level
- Base Stats
- Starting Ability IDs
- `WorldActorClass`

`WorldActorClass` must derive from `ADMFDigimonCharacter`. This guarantees the framework can initialize the spawned actor with the replicated instance ID/species/stats.

## 3. Create a starter roster

Create **Data Asset → DMFStarterRosterData** under `/Game/DigimonData`. Add starter entries and assign `DisplayOrder`.

Disabled entries remain in the asset but cannot be selected. The server re-checks this list, so a modified client cannot grant itself an arbitrary species.

## 4. Assign the roster

Open **Project Settings → Game → Digimon MMO Framework** and assign `Starter Roster`.

## 5. Optional custom UI / 3D preview

The native `UDMFStarterSelectionWidget` is fully functional and shows a textual stat preview.

For AAA presentation, create a Blueprint child of `UDMFStarterSelectionWidget`, bind/replace its layout, and implement `BP_OnStarterPreviewChanged`. Use the supplied species `PreviewMesh` or `WorldActorClass` in your preferred SceneCapture/preview-stage setup. This keeps visual preview logic client-side while selection authority remains server-side.

## 6. Runtime behavior

A new account has `bStarterSelected=false` and no active partner GUID. The owner sees starter selection automatically. On confirmation:

- requested species is checked against the server's roster;
- inventory capacity is checked;
- a new `FGuid` instance ID is generated by the server;
- species base stats and configured starter abilities are copied into the instance;
- the instance is marked as a starter partner;
- it is appended to the replicated inventory;
- it becomes the active partner;
- the account is saved immediately;
- its 3D actor is spawned if the species has a valid actor class;
- the UI closes after replicated onboarding state changes.

Returning players load the persisted GUID and do not receive another starter.

## 7. Administrative reset hook

`ResetStarterOnboarding` is `BlueprintAuthorityOnly` and intended for server-side administration/support or automated testing. With `bRemoveStarterDigimon=true`, it removes starter-marked instances, destroys the active partner actor, invalidates the active partner GUID, persists the account, and re-opens onboarding through replicated state. Do not expose this function directly to an untrusted client UI.

Starter selection requests return an owning-client result event (`OnStarterSelectionResult`) on both success and rejection, allowing custom UIs to restore controls and display authoritative validation errors.
